Factory Inventory Management System

A demo full-stack app for inventory, orders, demand forecasting, backlog and spending analytics. A Vue 3 single-page app talks over REST to a FastAPI service that serves in-memory data loaded from JSON files. There is no database.

System architecture

Two processes on localhost. The browser calls the API directly; there is no proxy, and the API URL is hardcoded in the client.

Data flow

What happens when a user changes a filter on the Dashboard.

  1. User picks a filterFilterBar writes to shared refs in useFilters (period, location, category, status).
  2. View reactsA watch on those refs in the view triggers a reload.
  3. Request is builtapi.js turns the filters into query params and skips any set to all.
  4. API filters in memoryThe route runs apply_filters (warehouse, category, status) and filter_by_month over the loaded lists.
  5. Response is validatedPydantic checks the rows against the response model and FastAPI returns JSON.
  6. UI re-rendersThe view stores the raw rows in refs; computed properties derive totals and chart series.

Server-side logic worth knowing

  • Dashboard summary is computed per request: inventory value, low-stock count (on hand at or below reorder point), pending orders (Processing or Backordered), backlog count and total order value.
  • Period filter accepts a month like 2025-01 or a quarter like Q1-2025, matched against order_date. Unknown quarters return unfiltered data.
  • Backlog responses add a has_purchase_order flag by checking the purchase-order list.
  • Reports aggregate orders by quarter and by month on every call; nothing is cached.
  • Inventory has no date field, so it ignores the period filter.

Frontend structure

Shared state

  • useFilters: module-level refs, so selections persist as you move between views.
  • useI18n: English and Japanese; locale saved in localStorage; currency follows locale (USD or JPY).
  • useAuth: a hardcoded mock user and task list, not real authentication.

Layout

  • App.vue holds the shell: header, FilterBar, profile menu, tasks modal and language switcher.
  • views/ has one page per route; components/ holds the modals and shell widgets.
  • Charts are hand-built SVG and CSS Grid, with no chart library.
